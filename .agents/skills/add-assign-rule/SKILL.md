# 배분 규칙 보강

## 언제 쓰는지

1. `web/engine.js`의 1순위 배분 정확도를 높여야 할 때 사용한다.
2. `data/시험_요구문항_40건.csv`의 오답 원인을 규칙 단위로 설명해야 할 때 사용한다.
3. 제외어 추가, 키워드 추가, 우선순위 변경 중 근거 있는 보강안을 검토할 때 사용한다.
4. 원본 배분기준표를 보존하면서 `rules_보강.csv` 사본을 만들어야 할 때 사용한다.
5. 시험 40건과 접수대장 520건에서 변경 전후 효과와 회귀 여부를 확인해야 할 때 사용한다.

## 순서

1. `AGENTS.md`, `PROGRESS.md`, `CONTEXT.md`, `처리지침.md` 제3장을 읽고 조직도 26개 과와 원본 배분기준표를 확인한다.
2. 원본 규칙으로 시험 40건과 접수대장 520건의 1순위 정확도를 계산하고, 시험 오답을 같은 키워드 충돌·제외어 부족·키워드 누락·우선순위 역전 등 원인별로 묶는다.
3. 원인마다 제외어 추가, 키워드 추가, 우선순위 변경 중 한 가지 방법을 제안하되 아직 파일을 바꾸지 말고 사용자의 선택을 기다린다.
4. 사용자가 고른 변경만 원본 배분기준표의 사본 `rules_보강.csv`에 반영한다. 변경 전후 시험 40건과 접수대장 520건의 1순위 정확도, 바로잡힌 문항, 새로 틀린 문항을 다시 계산한다.
5. 바꾼 규칙과 검증 결과를 `PROGRESS.md`에 기록하고, 변경 규칙·전후 정확도·새 오답 여부를 표로 보고한다.

## 끝나는 조건

1. 원본 배분기준표가 수정되지 않고 `rules_보강.csv`가 별도 사본으로 존재한다.
2. 사본과 원본의 차이가 사용자가 선택한 규칙에만 한정된다.
3. 시험 40건과 접수대장 520건의 변경 전후 1순위 정확도가 모두 계산된다.
4. 시험 1순위 정답이 30건 이상이고 기존 정답 중 새로 틀린 문항이 0건이다.
5. 변경 규칙과 결과가 `PROGRESS.md`에 기록되고 남은 일·막힌 점이 보고된다.

## 하지 말 것

1. 사용자가 선택하지 않은 제안이나 규칙을 사본에 반영하지 않는다.
2. 원본 `data/배분기준표_소관키워드_304건.csv`, 조직도, 시험 문항, 접수대장을 수정·삭제·덮어쓰지 않는다.
3. 조직도 26개 과 밖의 부서명을 추가하거나 후보로 사용하지 않는다.
4. 배분 규칙을 `web/engine.js`에 직접 쓰거나 특정 시험 문항의 정답을 예외 코드로 넣지 않는다.
5. 정확도 기준을 충족하지 못하거나 새 오답이 생겼는데 완료로 보고하지 않는다. 원인을 제시하고 다음 변경은 다시 사용자 선택을 받는다.
